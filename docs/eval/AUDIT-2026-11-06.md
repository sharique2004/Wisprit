## Seam 1 — capture: the parachute stalled every headset press ~3 s

`metrics.log` says every November row captured from
`CADefaultDeviceAggregate-<pid>-0` (`transport=aggregate`, 48 kHz). That is not
a device anyone chose: on macOS 27 an `AVAudioEngine` input node opens a
private aggregate of the default INPUT and default OUTPUT, clocked by the
output, and AVFoundation caches the AUHAL behind it across engine instances
(the same AUHAL pointer serves every utterance in the log). The attribution hid
the most important fact in the log: **20 of the 22 November utterance rows were
dictated through a classic-Bluetooth headset** (default output = a Bluetooth
UID, `SetBluetoothAudioFormatAndWait(104)`), until it disconnected at 02:36:16.

With a classic-BT primary the dual-capture parachute runs (by design), and it
was an `AVAudioEngine` pinned to the built-in mic. With the headset as the
default output, that engine spent **~3.0 s in
`SetBluetoothAudioFormatAndWait(…): Waiting for format change timed out` on
24 of its 32 opens** (the rest were cut short by an immediate stop) — and it
was started from the session thread (or from the prestart queue the session's
own `stop()` then waited on). What that did, from the rows:

| November headset rows (n=20) | value |
|---|---|
| median `held_ms` / median `audio_ms` | 1881 / **3000** |
| non-starved holds < 3 s that recorded ≥ 2.9 s of audio | **9 of 10** |
| `empty_reason=starved` (0 bytes reached the analyzer) | **7** |
| `silent` / `short_hold` | 6 / 2 |
| produced text | 5 (an 8.2 s hold produced three words) |
| `noise_floor` exactly 0.0 | **19 of 19** rows that carry it (Aug/Sep median ≈ 0.015) |

The 7 starved rows are the cascade: the session thread sat in the parachute's
start, presses queued behind it, the prestart hook's key-up handler saw no
utterance recording yet and stopped a primary mic that had been open < 1 s —
before the headset's SCO link delivered a byte. The zero noise floors are the
aggregate zero-filling its input until the input side runs, which also made
`first_chunk_ms` stop measuring SCO bring-up and kept the "Connecting headset
mic…" notice (keyed on a classic-BT `deviceFacts` and a nil first chunk) from
ever firing. After the headset disconnected, the cached aggregate AUHAL was
re-pointed while idle (142 → 173) and the next two built-in-mic holds were
**pure digital zero** (peak 0.0, VAD 0.0) — classified `silent`.

Diagnostics were noise too: **61** "microphone delivered no audio" lines for
**7** real 0-byte utterances — `MicCapture.stop()` logged on captures that had
never started (the parachute's, every utterance).

**Probe** (`Wisprit miclab`, now a backend A/B). Caveat: this agent's process has
no microphone grant, so the built-in mic delivers zeros here; latency,
attribution and reconfiguration are still measurable, and a BlackHole loopback
carries a real signal (`say -a`).

| | `engine` (AVAudioEngine) | `hal` (input-only AUHAL) |
|---|---|---|
| lands on (unpinned) | `CADefaultDeviceAggregate-<pid>-0` | the default input itself |
| start cost (built-in, 3 runs) | 150–226 ms | 79–100 ms |
| start cost (BlackHole, 5 runs, pinned) | 144–155 ms | 58–74 ms |
| first buffer | ~106 ms | ~106 ms (100 ms chunks, by design) |
| hardware-reconfigured notification on a pinned start | **5 of 5** | 0 of 5 |
| key-up partial chunk | dropped with the tap | delivered (2133 vs 2100 ms for the same 2 s) |
| loopback `say` → capture → `eval asr`, 5 sentences | same transcript as `hal` on 4/5; "band" → "van" on the fifth | — (one sentence's two captures were bit-identical PCM) |

Pinning the engine (the obvious fix) is ruled out by the 5/5 spurious
configuration changes: `MicCapture` must treat each as a dead capture.

**Fix (`HalInputUnit`, `MicCapture.Backend`).** The microphone is opened with
an input-only AUHAL on the actual input device — output disabled, so nothing
renegotiates a Bluetooth headset; a fresh AudioUnit per press, so nothing is
cached between utterances; the IO clocked by the mic, so silence is never
synthesized and `first_chunk_ms` is SCO bring-up again. Chunks are re-formed to
the 100 ms shape every consumer was measured on, off the real-time thread, and
the partial chunk at key-up is delivered instead of dropped. The engine path is
kept byte-for-byte behind `capture_backend = engine` and as the automatic
fallback when the AUHAL will not open. The parachute always uses the AUHAL and
opens/closes on its own queue, so no caller can wait on it; `MicCapture.start()`
no longer queues the session behind a start already in flight; `stop()` on a
capture that never opened is a silent no-op. The engine path's attribution now
names the aggregate's real input (`InputDeviceProbe.defaultInput()`), and every
utterance row gains `capture_backend` and `first_chunk_ms`.

## Seam 2 — the dictionary's fuzzy layer rewrote ordinary English

The fuzzy layer (Aug 24, verified on TTS only) was never run on real speech.
With dictionary on, LibriSpeech lost words at the `final` stage:

| `refine=off,dict=on`, lexicon = the app's (`--lexicon system`) | clean before → after | other before → after |
|---|---:|---:|
| repo fixture dictionary (9 terms) | 2.30% → **2.25%** | 6.04% → **5.47%** |
| the owner's dictionary (139 terms, local only, not committed) | 3.11% → **2.33%** | 6.27% → **5.50%** |
| clips rewritten, owner's dictionary (of 400) | 34 → **4** | |

Raw is 2.25% / 5.47%, so the owner's own dictionary cost **+0.86 / +0.80 pt**
(38 % / 15 % relative) of WER on read speech — larger than refine's whole
effect. 25 of its 38 rewrites were multi-word windows sharing an opening word
with a hear phrase: "and this"/"and thou" → Anthropic via "and thropic", "he
thought" → hackathon via "hacker thought", "well to"/"well as"/"well of" →
WellX via "well x", "the land"/"the man"/"the dawn" → a two-word place name
via "the …", "even if" → EventKit via "event kit", "back to" → BACnet via
"back net". The fixture shows the same shape: every one of its 10 rewrites was
"you can"/"you and"/"you want"/"you not" → Ubuntu via "you bantu", plus "in
some" → InsForge. Whole-window Jaro-Winkler is dominated by the shared prefix.
The rest were inflections the ordinary-word veto could not see, because the
lexicon lists base forms ("remained" → RamAIn via hear "remain", "letters",
"interests", "verses", "stamped").

**Fix (`FuzzyVocabularyCorrector`).** A window must now align with its hear
phrase word by word, by the same two floors; and a token whose regular-suffix
stem is an ordinary word is itself ordinary. The intended shapes still repair
("in forges" → InsForge, "wisper it" → Wisprit, "Shariqs" → Sharique), and
`--lexicon system` was added to the harness so the replay can use the app's
own lexicon (default unchanged: the compiled list).

tts-samantha `refine=off,dict=on`: WER 7.64% → **7.23%**, zero-edit 0.370 →
**0.407**, term recall 0.667 → 0.611 — the one term lost is "get up" → GitHub
(a window whose second word does not resemble "hub"); the same rule that drops
it is what stops "I get up at seven" becoming "I GitHub at seven". Two TTS
false positives also went away ("meeting is" → MeetingScribe, "next" eaten
next to PostgreSQL).

The shipped matrix (`refine=on,dict=on`, fixture, compiled lexicon), the same
refined text on both sides of each pair: ls-test-clean final 2.56% → **2.51%**,
ls-test-other 6.47% → **5.90%**. All four tts-samantha configurations stay
inside their BASELINE.json WER/CER/term-recall/zero-edit bands (`eval all`
exit 0); the battery band does not, for the reason in Q4.

Of the 4 rewrites left on the owner's dictionary, 3 are exact matches of hear
phrases that are themselves English words ("play" → Ploy, "remain" → RamAIn,
"Sarah" → SEERA) — the exact pass does what the dictionary says — and one is a
proper name the lexicon does not list ("Elsie" → EliseAI). **29 of the
owner's 404 hear phrases are single dictionary words** ("letter", "queen",
"archive", "orchestra", "play", "employ", "rack", …); each rewrites that word
everywhere. That is the owner's data to review, not code to change.

## Q2 — is the low level costing words? (yes, but gain cannot buy them back)

November peaks were 0.005–0.12 against 0.1–0.86 in August — but those rows are
the Bluetooth headset through the aggregate, whose true floors were masked to
0.0. Measured on 100 clips per rung, scaling each clip so its peak (the meter's
own statistic) lands at the live levels; `n-` adds a fixed mic floor (white,
RMS 0.00075 — the August built-in floor); `+norm` is the ORACLE utterance-level
gain (the rescue normalizer: target 0.5, cap 30 dB) — an upper bound on any
causal AGC.

| raw WER, 100 clips each | clean | clean +norm | other | other +norm |
|---|---:|---:|---:|---:|
| source (peaks p50 ≈ 0.6) | 1.81% | — | 5.60% | — |
| q-0.117 (attenuated only) | 2.01% | 1.86% | 6.77% | 5.60% |
| q-0.06 | 1.96% | 1.86% | 6.88% | 5.65% |
| q-0.011 | 2.31% | 1.71% | 8.05% | 5.86% |
| q-0.005 | 3.02% | (refused: < 0.01) | 9.65% | (refused) |
| n-0.117 (+ fixed mic floor) | 2.06% | 2.01% | 6.50% | 7.14% |
| n-0.06 | 2.41% | 2.56% | 7.57% | 7.36% |
| n-0.011 | 12.71% | 12.91% | 27.99% | 29.69% |
| n-0.005 | 45.93% | (refused) | 65.19% | (refused) |

One word is ≈ 0.05 pt here; differences under ~0.3 pt are noise. Read across:
attenuation alone (quantization the only added noise) costs little on clean
speech and 1.2–4 pt on `other` — the analyzer IS mildly level-sensitive, a
refinement of R19 — and the oracle gain recovers that part completely. But a
real microphone always has a floor under the speech, and with one the picture
inverts: the loss is an SNR loss, far larger at the low end, and even the
oracle gain does not recover it — it is a coin flip at the live levels
(n-0.117: −0.05 / +0.64 pt; n-0.06: +0.15 / −0.21 pt) and worse at the low
end (n-0.011: +0.20 / +1.70 pt). A causal live AGC can only do worse than the
oracle. **No AGC or pre-gain was added.** The existing rescue-only
normalization (peak window [0.01, 0.25)) stays the one place gain is applied.
`setVoiceProcessingEnabled` was not re-tried: its AGC rides with NS/AEC and
output ducking, the enhancement class R19 measured harmful.

What the November rows actually lacked was not gain but a working capture
(Seam 1): their 0.005–0.12 peaks came from a Bluetooth HFP mic read through a
zero-filling aggregate, and their floors were masked to 0.0, so the SNR was
unmeasurable. The headset `miclab` run below is how to read it.
