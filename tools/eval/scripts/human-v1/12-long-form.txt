I spent most of yesterday reading through how the insertion ladder actually decides which rung to use, and I think the thing that surprised me is how much of it is about the target application rather than about us. If the app has an input method connection we can stream into it directly, which is fast and undoable, and if it does not we fall back to pasting, which means touching the clipboard, which means restoring it afterwards, which means a delay that somebody has to have chosen a number for. And then there is the case where the field is secure, where we do nothing at all and say so. None of that is complicated on its own but the combination is where the bugs live, and the tests we have cover each rung and not the transitions between them. I want to write the transition tests before I change any of it.
Let me try to say the whole argument out loud, because I keep going in circles when I write it down. The claim is that raw word error rate has converged, so nobody wins on the acoustic model anymore, and the difference between a dictation tool people love and one they abandon is everything that happens after the transcript exists. That means the names they use, which a general model has never seen, and the formatting they expect, which depends on where they are typing, and the corrections they make afterwards, which nobody is currently learning from. If that is right then the roadmap writes itself: measure the gap honestly, fix the two defects that would poison anything built on top, get real human audio so the thresholds are tuned on something real, and only then start building the levers. If it is wrong, the harness will say so within a week, which is the whole reason it goes first.
